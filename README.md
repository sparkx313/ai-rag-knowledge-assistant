# Local Document RAG Assistant

Index local text documents into SQLite full-text search, retrieve the most relevant passages for a question, then send those passages to a local Ollama model for a cited answer. Sources are displayed beside every answer so you can check the evidence.

It works on files you provide. The app does not create a fake vector store, sample documents, or prewritten answers.

## Requirements

- Python 3.10 or newer
- An Ollama server with a local chat model installed
- SQLite built with FTS5 (included in most standard Python distributions)

Install the application dependency:

```bash
python -m pip install -r requirements.txt
```

## Run

Start Ollama on the same machine. Then set a folder and installed model, and launch the UI:

```bash
# macOS/Linux
export RAG_DOCUMENTS_DIR=/absolute/path/to/your/notes
export OLLAMA_MODEL=your-installed-model
streamlit run app.py --server.address 127.0.0.1
```

```powershell
$env:RAG_DOCUMENTS_DIR = "C:\Users\you\Documents\notes"
$env:OLLAMA_MODEL = "your-installed-model"
streamlit run app.py --server.address 127.0.0.1
```

The default model endpoint is `http://127.0.0.1:11434`. You can also set `RAG_DB_PATH`, `OLLAMA_URL`, and the same values in the sidebar. Select **Index or refresh documents**, enter a question, and select **Ask**.

## Indexed files and retrieval

- Reads UTF-8 text files with `.txt`, `.md`, `.rst`, `.py`, `.json`, `.yaml`, `.yml`, `.toml`, and `.csv` extensions.
- Splits documents into overlapping text passages and keeps their relative file paths and chunk numbers in a local SQLite index.
- Uses SQLite FTS5 BM25 lexical retrieval. It does not create embeddings, require ChromaDB, or pretend that keyword search is vector search.
- Skips hidden directories, common environment/build directories, and individual files larger than 5 MB. Changed, unchanged, removed, and unreadable files are reported during indexing.

The assistant sends the question and retrieved passages to the configured Ollama [`/api/chat` endpoint](https://github.com/ollama/ollama/blob/main/docs/api.md) with streaming disabled. By default, that endpoint is local. If you change the endpoint to a remote server, those passages are sent to that server. Do not index material you are not allowed to share with the configured model host.

The prompt asks the model to answer from retrieved passages, treat document text as untrusted data, and cite source labels. The answer is still generated by a language model; review the displayed passages and citations before relying on it.

## Docker

Build the UI image and mount your documents and a persistent index directory. The example connects the container to Ollama running on the host and binds the web UI to localhost:

```bash
docker build -t local-document-rag .
docker run --rm -p 127.0.0.1:8501:8501 \
  --add-host=host.docker.internal:host-gateway \
  -v "$PWD/notes:/docs:ro" -v "$PWD/rag-data:/data" \
  -e RAG_DOCUMENTS_DIR=/docs -e RAG_DB_PATH=/data/knowledge.sqlite \
  -e OLLAMA_URL=http://host.docker.internal:11434 -e OLLAMA_MODEL=your-installed-model \
  local-document-rag
```

## Limits

- PDF and Word files are not parsed; convert them to text or Markdown before indexing.
- Retrieval is lexical, not semantic. It may miss relevant passages that use different words from the question.
- The app is single-user, has no chat-history store, and does not provide a hosted API or user authentication.
